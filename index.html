About

I work at the intersection of cloud infrastructure, automation, and governance. My focus is on designing environments that are reproducible, secure by default, and easy to reason about — whether that means writing infrastructure as code, enforcing policy at scale, or automating the operational work that keeps systems running smoothly.

I'm comfortable working across both Google Cloud Platform and Microsoft Azure, and I care about the practices that make cloud environments maintainable over time: version-controlled infrastructure, consistent policy enforcement, clear automation, and documentation that keeps pace with the systems it describes.

How I Approach Infrastructure

The principles that guide how I design, automate, and govern cloud environments.

Infrastructure as Code

I treat infrastructure definitions as code: version-controlled, reviewed, and repeatable. Using Terraform, I aim for environments that can be recreated confidently rather than reconstructed from memory or manual steps.

Automation

Repetitive operational work is a candidate for automation. I use scripting with Bash and PowerShell, along with AI-assisted tooling, to reduce manual effort and the risk of human error in routine tasks.

Cloud Governance

Consistent policy enforcement keeps environments compliant and predictable as they grow. I use Azure Policy to define and apply guardrails, so that governance is built into the environment rather than checked after the fact.
